## 1. 문제 정의

### 1.1 발견된 갭 4가지

홈페이지와 실제 리포트를 대조 분석한 결과, 고객이 **"기대한 것"과 "받은 것"** 사이에 4가지 불일치가 존재한다.

| #    | 홈페이지가 약속하는 것                            | 리포트가 실제로 주는 것                                                                             | 갭 유형     |
| ---- | ------------------------------------------------- | --------------------------------------------------------------------------------------------------- | ----------- |
| G-01 | "마케팅에 돈을 쓰는데" → 마케팅 전반 진단 암시    | 웹사이트 SEO/GEO/기술 인프라 진단                                                                   | **범위 갭** |
| G-02 | "비즈니스 영향도" + "점수를 비즈니스 언어로 번역" | "바운스율 60% 증가", "전환율 25% 향상" (여전히 마케팅 전문용어)                                     | **언어 갭** |
| G-03 | "뭘 먼저 고쳐야 ROI가 올라가는지 우선순위"        | 높음/보통/낮음 라벨 + 점수 영향(+9점, +7점)만 존재. 왜 이 순서인지 설명 없음                        | **근거 갭** |
| G-04 | "AI 마케팅 진단 서비스"를 표방                    | 자체 사이트가 SEO/GEO 기본기 미달 (종합 71점, 심각 12개). 고객이 Findably 자체를 진단하면 신뢰 하락 | **신뢰 갭** |

**부수 갭**: 비교 테이블에서 "대형 컨설팅펌 / 마케팅 에이전시"와 동급 비교 → 고객 기대를 과도하게 높임

### 1.2 영향 범위

- **고객 신뢰**: 기대-경험 갭은 NPS 하락, 무료→유료 전환율 저하의 직접 원인
- **마케팅 효율**: 홈페이지 카피의 공감력은 높지만, 리포트에서 약속을 이행하지 못하면 입소문(바이럴)이 작동하지 않음
- **기존 PRD와의 관계**: F-01 돈 번역기(Revenue Translator)가 이미 기획되어 있으나, 리포트 영향도 섹션에 적용 위치가 구체적이지 않았음

### 1.3 해결 원칙

1. **제품 범위(웹사이트 SEO/GEO 진단)는 변경하지 않는다** — 범위를 넓히는 것은 스코프 크리프
2. **"왜 이것이 마케팅의 첫 번째 단계인가"라는 스토리를 심는다** — 프레이밍 변경
3. **홈페이지와 리포트 양쪽을 동시에 수정한다** — 한쪽만 바꾸면 갭이 이동할 뿐
4. **자기 사이트부터 완벽하게 만든다** — "대장간의 식칼" 원칙. 진단 서비스가 자기 진단에서 낮은 점수면 신뢰 붕괴
5. **기존 Epic 구조에 Task로 추가한다** — 새 Epic 없음

### 영역 A — 홈페이지 프레이밍 수정

#### Task A-01 (8.10): 모토/서브카피 수정

**소속 Epic**: Epic 8 (랜딩페이지)  
**예상 소요**: 30분  
**난이도**: 쉬움 (텍스트 변경만)  
**의존**: 없음 (즉시 실행 가능)  
**해결하는 갭**: G-01 (범위 갭)

**현재 (AS-IS)**

```
H1: "마케팅에 돈 쓰는데 뭘 먼저 고쳐야 하는지 모르겠다면"

Sub: "SEO, GEO, 콘텐츠, 기술 — 60초 만에 진단하고,
      뭘 먼저 고쳐야 ROI가 올라가는지 우선순위로 알려드립니다."
```

**문제**: H1이 "마케팅 전반"을 암시하여 리포트(웹사이트 진단)와 범위 불일치

**수정 후 (TO-BE)**

```
H1: "마케팅에 돈을 쓰는데, 어디서 새고 있는지 모르겠다면"

Sub: "웹사이트에서 새는 마케팅 비용부터 찾아드립니다.
      SEO, AI 검색(GEO), 콘텐츠, 기술 인프라 — 60개 항목을 진단하고
      가장 돈이 많이 새는 곳부터 고치는 순서를 알려드립니다."
```

**변경 포인트**:

- "뭘 먼저 고쳐야 하는지" → "어디서 새고 있는지": 웹사이트 = 마케팅이 새는 구멍이라는 프레이밍
- "웹사이트에서 새는"이라는 한정어 추가: 진단 범위를 명시
- "가장 돈이 많이 새는 곳부터": 우선순위의 기준이 "돈"임을 선언

**추가 수정 — 3가지 고민 카드**:

현재 첫 번째 카드:

```
💸 "돈은 쓰는데 뭐가 효과인지 모르겠다"
   항목별 ROI 영향도 + 실행 우선순위 제공
```

수정 후:

```
💸 "마케팅비 쓰는데 어디서 새는지 모르겠다"
   항목별 매출 영향 금액 환산 + 가장 큰 구멍부터 막는 순서 제공
```

**완료 기준**:

- [ ] H1 텍스트 변경 반영
- [ ] 서브카피 텍스트 변경 반영
- [ ] 고민 카드 1번 텍스트 변경 반영
- [ ] 모바일에서 H1 줄바꿈 깨지지 않는지 확인
- [ ] OG 태그(og:title, og:description)도 동일하게 수정

#### Task A-02 (8.11): 비교 테이블 리프레이밍

**소속 Epic**: Epic 8 (랜딩페이지)  
**예상 소요**: 30분  
**난이도**: 쉬움 (텍스트 변경만)  
**의존**: 없음  
**해결하는 갭**: G-01 (범위 갭) — 과대 포지셔닝 완화

**현재 (AS-IS)**

```
섹션 제목: "마케팅 진단, 어디서 받으시나요?"
부제: "같은 '마케팅 감사'도 범위와 방식이 다릅니다"

컬럼: 대형 컨설팅펌* | 마케팅 에이전시* | Findably
```

**문제**: 컨설팅펌(전략+조직 변화), 에이전시(실행 대행)와 동급 비교 → 고객이 "Findably = 컨설팅 자동화"로 오해

**수정 후 (TO-BE)**

```
섹션 제목: "마케팅 진단의 첫 번째 단계, 어떻게 시작하시나요?"
부제: "전략을 세우기 전에, 먼저 새는 곳을 찾아야 합니다"

컬럼: 마케팅 전략 컨설팅* | 마케팅 실행 대행* | 마케팅 기초체력 진단 (Findably)
```

**테이블 하단 주석 추가**:

```
💡 컨설팅은 전략을, 에이전시는 실행을, Findably는 그 전에 새고 있는 구멍을 찾아드립니다.
   전략과 실행이 효과를 내려면, 먼저 기초체력이 갖춰져야 합니다.
   Findably로 기초체력을 확보한 후, 필요하다면 전략 컨설팅이나 실행 대행을 검토하세요.
```

**완료 기준**:

- [ ] 섹션 제목/부제 변경 반영
- [ ] 테이블 컬럼 헤더 변경 반영
- [ ] 하단 주석 추가 반영
- [ ] Findably 컬럼 헤더에 "(Findably)" 표기 유지

### 영역 B — 리포트 프레이밍 보강

#### Task B-01 (7.12): 리포트 도입부 "마케팅 누수 브릿지" 섹션 추가

**소속 Epic**: Epic 7 (리포트)  
**예상 소요**: 1~2시간  
**난이도**: 보통 (리포트 템플릿 구조 변경)  
**의존**: 없음 (독립 실행 가능)  
**해결하는 갭**: G-01 (범위 갭)

**현재 (AS-IS)**

리포트 구조:

```
경영진 요약 → SWOT 분석 → 90일 실행 로드맵 → AI 인용 추적 → ...
```

경영진 요약이 바로 기술적 내용("Core Web Vitals 미달", "Canonical URL 미설정")으로 진입.  
"왜 웹사이트 진단이 마케팅 전체에서 중요한지"에 대한 컨텍스트 없음.

**수정 후 (TO-BE)**

리포트 구조 (도입부 추가):

```
🆕 마케팅 비용이 새는 곳을 찾았습니다 (브릿지 섹션)
   → 경영진 요약
   → SWOT 분석
   → 90일 실행 로드맵
   → ...
```

**브릿지 섹션 콘텐츠**:

```markdown
## 마케팅 비용이 새는 곳을 찾았습니다

광고를 돌려도, SNS를 해도, 콘텐츠를 만들어도 —
고객이 당신의 웹사이트를 **검색에서 찾을 수 없거나**,
**찾았는데 느려서 떠나거나**, **AI에게 물어봤는데 추천받지 못하면**,
모든 마케팅 비용이 새고 있는 겁니다.

이 리포트는 **웹사이트에서 새고 있는 마케팅 비용의 구멍**을 찾아서,
**어디를 먼저 막아야 하는지** 알려드립니다.

| 진단 영역            | 마케팅에서의 의미                         |    이 사이트 점수     |
| -------------------- | ----------------------------------------- | :-------------------: |
| SEO (검색 최적화)    | Google에서 고객이 당신을 찾을 수 있는가   |    {seo_score}/100    |
| GEO (AI 검색 최적화) | ChatGPT, Perplexity가 당신을 추천하는가   |    {geo_score}/100    |
| 콘텐츠               | 방문한 고객이 신뢰하고 행동하는가         |  {content_score}/100  |
| 기술 인프라          | 고객이 떠나지 않을 만큼 빠르고 안정적인가 | {technical_score}/100 |

💰 **이 리포트의 진단 결과를 모두 개선하면,
월 약 {total_monthly_impact}만원의 추가 마케팅 효과를 기대할 수 있습니다.**
_(업종 평균 벤치마크 기준 추정치이며, 실제 결과와 다를 수 있습니다)_
```

**기술 구현**:

- 리포트 생성 템플릿에 `BridgeSection` 컴포넌트 추가
- 각 영역 점수는 기존 진단 결과에서 가져옴 (신규 데이터 불필요)
- `total_monthly_impact`는 C-01 Task의 원화 환산 로직 완성 후 연동 (선행 없이도 "추정 중" 표시 가능)

**완료 기준**:

- [ ] BridgeSection 컴포넌트가 리포트 최상단(경영진 요약 위)에 렌더링
- [ ] 4개 영역 점수가 실제 진단 결과와 일치
- [ ] 총 매출 영향 금액이 표시 (C-01 완료 전에는 "분석 준비 중" 또는 placeholder)
- [ ] PDF 리포트에도 동일하게 반영

## 9. "대장간의 식칼" — 마케팅 활용 계획

영역 E 완료 후, Findably 자체 사이트의 Before→After를 마케팅 자산으로 활용한다.

**활용 방식**:

1. **샘플 리포트**: 홈페이지의 "샘플 리포트" 링크에 **Findably 자체 진단 결과**를 Before/After로 제공
   - Before: 71점 (심각 12개) → After: 90점+ (심각 0개)
   - "우리가 직접 써서 이만큼 올렸습니다"

2. **바이럴 콘텐츠**: Before/After 갭을 소셜 미디어용 카드로 제작
   - "마케팅 진단 서비스가 자기 사이트도 못 고치면? → 우리는 직접 고쳤습니다"
   - 기존 마케팅 전략 v1.0의 "Before/After 바이럴" 채널과 연동

3. **신뢰 신호**: 홈페이지에 자체 진단 점수 배지 표시
   - "이 사이트는 Findably로 진단하여 90점+를 유지하고 있습니다"
   - 실시간 업데이트 (Starter 구독 기능의 데모)

## 10. 개발 효율화 가이드 — Skill / Agent / MCP 활용법

> 이 섹션은 PRD 본문이 아니라, 17개 Task를 Claude Code에서 효율적으로 실행하기 위한 **개발 운영 가이드**입니다.

### 10.1 Phase별 최적 도구 매핑

```
Phase 0 (텍스트/파일) → Sonnet 4.6 단독, 서브에이전트 불필요
Phase 1 (리포트 템플릿) → Sonnet 4.6 + code-reviewer 서브에이전트
Phase 2 (비주얼) → Sonnet 4.6 + Canva MCP (이미지 제작)
Phase 3 (성능) → Sonnet 4.6 + /loop (성능 모니터링)
Phase 4 (Revenue) → Opus 4.6 (환산 로직 설계) + Sonnet (구현)
Phase 5 (검증) → security-reviewer 서브에이전트 + Findably 자체 진단
```

### 10.2 Skill 활용

Claude Code의 `.claude/skills/` 에 이 PRD 전용 스킬을 생성하여 반복 작업을 자동화합니다.

**스킬 1: SEO 메타 검증 스킬**

```markdown

effort: low

---

아래 항목을 검증하세요:

1. canonical URL 존재 여부
2. og:title, og:description, og:image, og:url 4개 모두 존재
3. Title 태그 50자 이내
4. H1 태그 정확히 1개
5. robots.txt, sitemap.xml 접근 가능
6. JSON-LD Schema 에러 0건 (Google Rich Results Test API)

결과를 체크리스트 형식으로 보고하세요.
```

**스킬 2: 리포트 정합성 검증 스킬**

```markdown

name: report-consistency
description: 홈페이지 카피와 리포트 프레이밍 일치 여부 자동 검증

---

홈페이지의 H1, Sub, 고민카드, 비교 테이블 텍스트를 추출하고,
리포트 템플릿의 브릿지 섹션, 경영진 요약, 우선순위 설명과 대조하여
"약속-이행" 매핑 일치 여부를 검증하세요.

불일치 항목은 [홈페이지 텍스트] vs [리포트 텍스트] 형식으로 보고하세요.
```

### 10.6 병렬 실행 가능한 Task 그룹

동일 Phase 내에서 **파일 소유권이 겹치지 않는** Task는 서브에이전트로 병렬 실행 가능합니다.

```
Phase 0 병렬 그룹:
  [그룹 1] A-01 + A-02 (홈페이지 카피 파일)
  [그룹 2] E-01 (app/robots.ts, app/sitemap.ts, public/llms.txt)
  [그룹 3] E-02 (app/layout.tsx metadata)
  → 그룹 1·2·3 동시 실행 가능 (파일 충돌 없음)
  → B-02는 리포트 템플릿 파일이므로 독립 실행 가능

Phase 1 병렬 그룹:
  [그룹 1] B-01 + B-03 (리포트 템플릿 — 다른 섹션이므로 병렬 가능)
  [그룹 2] E-04 + E-05 (홈페이지 — H1 보조 텍스트 + FAQ 섹션)
  → 주의: E-04는 A-01 완료 후에만 시작
```
