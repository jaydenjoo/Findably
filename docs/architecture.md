### ADR-001: 4-Layer 크롤링 아키텍처

- **날짜**: 2026-03-13
- **상태**: ✅ 승인됨
- **맥락**: SEO/GEO 진단에 필요한 다양한 데이터를 수집해야 함. 비용 0원 유지 필요.
- **선택지**:
  - A: 단일 크롤러 (Playwright만) — 장점: 단순 / 단점: 외부 API 데이터 없음
  - B: 4-Layer (Playwright + Google API + 오픈소스 + 유료) — 장점: 포괄적 / 단점: 복잡도
- **결정**: B (4-Layer)
- **이유**: Layer 1~3은 비용 0원, Layer 4는 성장 후 단계적 도입
- **결과**: 60개+ 진단 항목 데이터 수집 가능, 무료 진단도 충분한 품질

### ADR-002: n8n v2 병렬 워크플로우

- **날짜**: 2026-03-16
- **상태**: ✅ 승인됨
- **맥락**: v1 순차 크롤링 ~90초 → 사용자 대기 시간 과다
- **선택지**:
  - A: 순차 실행 유지 (안정성) — 장점: 단순 / 단점: 90초
  - B: 3-Group 병렬 실행 — 장점: ~35초 / 단점: 복잡도, 장애 격리 필요
- **결정**: B (3-Group 병렬)
- **이유**: 사용자 경험 2.5배 개선, continueOnFail로 장애 격리
- **결과**: 10개 소스 병렬 수집, dataCompleteness로 품질 보장

### ADR-003: Firecrawl 통합 (마크다운 + 사이트맵)

- **날짜**: 2026-03-17
- **상태**: ✅ 승인됨
- **맥락**: AI 콘텐츠 분석에 정제된 마크다운 필요. Playwright raw HTML로는 노이즈 과다.
- **선택지**:
  - A: 자체 HTML→마크다운 변환 — 장점: 의존성 없음 / 단점: 품질 낮음, 유지비용
  - B: Firecrawl API (scrape + map) — 장점: 고품질 마크다운, 사이트 URL 맵 / 단점: 유료 API
- **결정**: B (Firecrawl)
- **이유**: 마크다운 변환 품질이 AI 분석 정확도에 직결. 비용은 유료 진단에서만 발생 (~건당 수십 원)
- **결과**: `lib/adapters/crawler.ts`로 어댑터 패턴 적용, 실패 시 graceful fallback (firecrawlUsed: false)
